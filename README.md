# MedAI Assistant - End-to-End Project Documentation

The **MedAI Assistant** is an advanced, full-stack telehealth and AI-triage platform designed to bridge the gap between preliminary patient symptoms and clinical workflows. The application utilizes a robust Python back-end paired with specialized Large Language Models to diagnose, translate, and route patients to live medical professionals based on their specific health profiles.

---

## 1. System Architecture & Tech Stack

### Back-End (Server)
- **Framework:** Python Flask (REST API architecture)
- **Database:** MySQL
- **ORM:** SQLAlchemy (`Flask-SQLAlchemy`)
- **Authentication:** JWT (JSON Web Tokens via `flask_jwt_extended`)
- **Document Generation:** ReportLab (for structured PDF generation with native Indic font support)
- **TTS (Text-to-Speech):** `gTTS` mapping patient reports into consumable audio files.

### Front-End (Client)
- **UI Framework:** HTML5, CSS3, Bootstrap 5 (Responsive Layouts & Grid Systems)
- **JavaScript:** Vanilla JS with native ES6 `fetch()` Async/Await wrappers
- **Icons & Styling:** FontAwesome, custom CSS glassmorphism widgets (`.glass-card`), dynamic fade-in animations

### Third-Party APIs & External Integrations
- **AI Triage Engine:** Groq API leveraging **Llama-3-8B** for lighting-fast medical evaluations, symptom NLP extraction, and translation pipelines.
- **External WebRTC Integration:** **Jitsi Meet** natively bound into the DOM via raw routing identifiers to handle zero-cost, serverless Video/Audio conferencing.

## 2. Core User Roles & Workflows

### 💻 A. Patient Portal
Patients register and maintain a direct channel with the AI or human specialists.
1. **Multilingual AI Consultation:**
   - Patients select a preferred language (English, Hindi, Telugu, Marathi).
   - They chat naturally about their symptoms.
   - The AI identifies the `Severity` (Normal vs. Critical/Moderate).
2. **Clinical Report Generation:**
   - The AI packages the chat into an official Medical Report including symptoms, structured analysis, and an audio transcription.
   - If Severity is `Moderate/Critical`, the system aggressively prompts the patient to consult a live specialist immediately.
3. **Wallet & Financial System:**
   - Patients maintain an internal digital wallet.
   - If a Patient books a doctor, their Wallet balance is automatically checked against the specific doctor's consultation fee. If sufficient, funds are debited via double-entry `Transactions`.
4. **Emergency Telehealth Module:**
   - Located on the Chat interface, an urgent **Red Emergency Button**.
   - Initiates immediate Jitsi WebRTC pipelines (Video Call, Audio-Only, or Email) routing directly to online specialists. Video calls execute a 2-way backend ringing handshake to notify the doctor.

### 🩺 B. Doctor Dashboard
Doctors log in to manage their physical appointments and incoming AI-routed reports.
1. **Report Validation:**
   - Open pending Patient Reports forwarded by the AI.
   - Provide an "Official Doctor's Response" which permanently overwrites the pending AI state and locks the case as `Completed`.
2. **Analytics & Financials:**
   - Profile tab tracks **Total Earnings**, **Cases Solved**, and **Live Feedback**.
   - Earnings automatically accrue whenever a patient assigns an AI Report to them or schedules an Appointment. 
3. **Incoming Emergency Desk:**
   - Receives instant, high-priority JavaScript modal overlays whenever a patient dials an Emergency Video Call. Clicking "Accept" launches a secure Jitsi Meet room identically matched to the patient.

### 👑 C. Administrative Console
A monolithic oversight dashboard reserved for hospital admins to evaluate macroeconomic data.
1. **User Oversight:** Tables mapping total registered Doctors and Patients.
2. **Approvals:** Directly govern Doctor onboardings and manage clinic specializations.

## 3. Database Schema (`models.py`)

The application enforces data strictness utilizing MySQL relational mapping tools.

- **`Admin`**: Handles system superusers (`admin_id`, `username`, `password_hash`).
- **`Doctor`**: Handles clinical profiles (`doctor_id`, `name`, `specialization`, `experience_years`, `total_earnings`, `available`, `phone`, `email`).
- **`Patient`**: Handles user profiles and global financing (`patient_id`, `name`, `wallet_balance`).
- **`PatientReport`**: Represents the core bridging object generated by the AI (`report_id`, `symptoms_text`, `ai_generated_report`, `severity_level`, `doctor_response`, `assigned_doctor_id`, `status`). Enforces dual-language pipelines (storing `_english` backups alongside localized text).
- **`Appointment`**: Schedules general clinical visits (`appointment_id`, `date`, `status`, `payment_status`).
- **`Transaction`**: Immutable double-entry ledger keeping track of deposits, debits (Patient), and credits (Doctor earnings).
- **`EmergencyCall`**: Temporary WebRTC handshake state machine managing `ringing`, `accepted`, or `ended` statuses.
- **`Feedback`**: Connects Patient ratings globally to Doctor profiles.

## 4. Notable AI & Algorithmic Mechanics

### Global English Enforcements (Bilingual Firewall)
To ensure the clinical dashboard remains parseable for a universally-trained doctor demographic, the overarching AI structure parses Patient input in their **native language**, but silently translates backend dependencies into **strict English** before committing to the database.
- *Dynamic Translations*: When clicking `Download PDF` inside the Web Portal, the Python backend executes a real-time reverse translation over the LLM to output the medical PDF in the specific language requested by the Patient dynamically.

### Financial Escrows inside REST APIs
Every assignment or booking endpoint executes synchronous validations:
1. `GET /patient/wallet` for fund availability.
2. `IF patient.balance < doctor.fee THEN Reject(400)`.
3. Generate simultaneous `DEBIT` / `CREDIT` `Transaction` objects ensuring zero financial drift.

## 5. Security & Deployment Posture
- All endpoint resources (except login/registration routes) are aggressively secured behind `@jwt_required()` decorators.
- Backend CORS mapping handles strict origin tracking.
- Passwords are encrypted natively through `werkzeug.security` (SHA256 salted).
